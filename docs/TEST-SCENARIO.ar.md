# جرد هيونداي — تجربة مثل الشغل الحقيقي

هذا سيناريو يدوي للوحة + تطبيق أندرويد. البيانات والأسعار وأرقام الشواصي **تجريبية، مو مخزون للبيع ولا هويات سيارات حقيقية**. نجاح اختبارات السيرفر ما يغني عن تجربة كاميرا وموقع على موبايل حقيقي.

## 1. قبل لا تبدي

- وقف الباك إند قبل تحديث الملفات وخذ نسخة احتياطية من قاعدة البيانات الفعلية. إذا SQLite، انسخ ملفها وملفات `-wal` و`-shm` إذا موجودات وهي مطفأة. لا تحذف قاعدة قديمة حتى لو بيها اختبارات سابقة.
- افتح CMD على وندوز ونفذ:

```bat
cd /d "C:\Users\Acer 5\hyundai-stock"
git switch main
git pull --ff-only origin main
dotnet test HyundaiStock.sln
set ASPNETCORE_ENVIRONMENT=Development
set Seed__Demo=true
set Seed__DemoPassword=Test1234
set ReverseProxy__PublicOrigin=https://hyundai.cloudapps.trade
dotnet run --project src\HyundaiStock.Web --urls http://127.0.0.1:5169
```

خلي إعدادات قاعدة البيانات و`Jwt:Key` الموجودة عندك مثل ما هي؛ هذي الأوامر ما تبدلها. كلمة السر أعلاه للتجربة فقط وتكدر تبدلها **قبل أول تشغيل**. لا تكتب أي مفتاح حقيقي بالريبو.

- الـ seed يشتغل حصراً ببيئة `Development` ولما `Seed:Demo=true`. بـ Production يتجاهل العلم ويكتب تحذير، وما يضيف داتا تجريبية.
- أول تشغيل يضيف 5 فروع (المنصور، الكرادة، زيونة، البصرة، أربيل)، مخزنين تجريبيين لكل فرع، 12 حساب، و3 جلسات: جلستين قديمات وجلسة جرد حية إذا ماكو جلسة حية موجودة. يختار سنوات جلسات غير مستخدمة حتى ما يتعارض ويا جلسة قديمة؛ ممكن سنة الجلسة التجريبية تختلف عن السنة الحالية. كل جلسة بيها 400 سطر مخزون (40 رقم قطعة × 10 مخازن)، إضافة مثبتة واحدة، و30 سيارة متوقعة. الوصف بيه التصنيف والعربي والإنكليزي؛ الأسعار بالدينار العراقي تقريبية.
- ما يعيد كلمات سر أو صلاحيات الحسابات القديمة، ولا يغير عدّ قديم أو يفتح جلسة مغلقة. علامة `demo-live-v1` تمنع تكرار الداتا حتى بعد ما تغيّرها أو تكمل الجلسة. تغيير كلمة سر الـ seed بعد أول مرة ما يغيّر حسابات موجودة.
- إذا أكو جلسة جرد حية قديمة، يتركها الوحيدة الحية ويضيف الجلسات التجريبية **مكتملة**؛ لا يخلط قطع جديدة بجلسة شغالة. حتى تمشي هذا السيناريو من البداية، استخدم قاعدة SQLite منفصلة للتجربة، مو قاعدة الشغل.
- إذا أرقام الحسابات أو أرقام المخازن التجريبية مستخدمة، يوقف برسالة واضحة ويرجع كل إضافاته، بدون تغيير القديم. إذا اسم فرع موجود يستخدم نفس الفرع ورقمه الموجود، وما يغير الرقم.
- إذا تريد تجربة نظيفة مستقلة: بنفس CMD وقبل التشغيل نفذ التالي (اترك إعداد JWT الحالي). هذا يبدّل قاعدة **هذه النافذة فقط**:

```bat
if not exist src\HyundaiStock.Web\App_Data mkdir src\HyundaiStock.Web\App_Data
set Database__Provider=Sqlite
set ConnectionStrings__Default=Data Source=App_Data/hyundai-demo.db
```

تأكد مجلد `src\HyundaiStock.Web\App_Data` موجود. لا تستخدم نفس اسم قاعدة الشغل بالغلط. لإلغاء التبديل لاحقاً: `set ConnectionStrings__Default=` و`set Database__Provider=` ثم رجّع تشغيل البرنامج.

## 3. تأكد من الرابط والتسجيل

1. شغل الباك إند على 5169 والـ relay بنفس الوقت؛ لا تخلط هذا ويا بورت صفحة السيناريو 5179.
   - المتوقع: اللوحة المحلية تفتح، والرابط العام ما يطلع `Backend offline` أو `Local backend unavailable`.
2. من نافذة خاصة بدون حساب افتح `https://hyundai.cloudapps.trade/Requests`.
   - المتوقع: يتحول إلى **https** `/Account/Login?ReturnUrl=...`، بدون نزول إلى http وبدون 500.
3. ادخل بالمسؤول التجريبي. افتح الرئيسية، المستخدمين، المشرفين، الفروع، المخازن، الطلبات، إضافة قطعة، قطع الغيار، الفروقات، المركبات والجلسات.
   - المتوقع: صفحات سليمة وداتا متعددة، وفروقات نقص وزيادة وأسعار غير صفرية. تصحيح VIN يظهر فقط للأدوار المخولة (أدمن الفرع ومدير المخزن)، مو كل دور.
4. جرّب كلمة سر غلط وحساب معطّل. جرّب دخول المحاسب من التطبيق.
   - المتوقع: رفض واضح، بدون دخول أو JWT. التطبيق فقط لموظفي الجرد.

## 5. إعادة العد وتصحيح كمية

1. مدير المخزن يدخل اللوحة ويفتح تفاصيل `58101D3A01` بمخزن 9011 ويسوي طلب إعادة عد لأحمد.
   - المتوقع: الطلب يظهر بالتطبيق/إعادة العد، المحاسب ما يقدر يطلب إعادة عد.
2. أحمد يعدّها 10 بنفس الموقع وبـ GPS صحيح.
   - المتوقع: إعادة العد مكتملة وسجل القطعة محافظ على التاريخ.
3. أحمد يرسل طلب تعديل كمية لنفس القطعة من 10 إلى **11** وسبب «كارتون إضافي بعد المطابقة».
   - المتوقع: بالتطبيق «بانتظار مدير المخزن»، وباللوحة طلب مربوط بنفس القطعة والمخزن.
4. المحاسب يحاول يوافق قبل المدير؛ بعدها مدير المخزن يوافق.
   - المتوقع: محاولة المحاسب الأولى تنرفض، وبعد المدير يصير «بانتظار المالية» والكمية تبقى 10.
5. محاسب المنصور يوافق نهائياً.
   - المتوقع: الطلب «مقبول»، الكمية **11** بالتطبيق واللوحة؛ فرق القطعة +2 وقيمته 170,000 د.ع. سجل موافقات وتغيير واحد فقط.
6. حدث الصفحة وأعد نفس الموافقة من تبويب ثانٍ.
   - المتوقع: ماكو تعديل مزدوج ولا سجل قبول نهائي ثاني. إذا قاعدة SQLite مشغولة، تظهر «قاعدة البيانات مشغولة، حدّث حالة الطلب قبل إعادة المحاولة» بدل انتظار طويل. افحص الحالة أولاً قبل الإعادة؛ لا تكرر POST عمياني.
7. بطلب ثاني اختبر الرفض من المدير، وبثالث اختبر رفض المحاسب بعد موافقة المدير، واكتب سبب واضح.
   - المتوقع: «مرفوض»، السبب والتاريخ محفوظات، والكمية ما تتغير.

## 6. قطعة غير موجودة

1. أحمد يمسح `QA2630035506` ويرسل طلب إضافة، وصف «جلدة باب تجريبية / Door seal»، كمية 2، موقع `QA-Z-01`، GPS حقيقي.
   - المتوقع: ما تنخلق قطعة بالجرد قبل الموافقات؛ الطلب يظهر عند مدير القطع.
2. مدير القطع يوافق؛ المحاسب يثبت.
   - المتوقع: «مثبت» بالتطبيق واللوحة؛ قطعة واحدة فقط، كمية النظام 0 والمعدودة 2. السعر 0 لأن طلب الإضافة الحالي ما يحدد سعر؛ لا تعتبر قيمته المالية مكتملة.
3. طلب إضافة ثاني برمز جديد: مدير القطع يرجعه بسبب «الوصف ناقص»، وأحمد يلغيه.
   - المتوقع: «رجع للموظف» ثم «ملغي»، التاريخ محفوظ، ما تنضاف قطعة. إعادة طلب مفتوح بنفس الرمز تترفض 409، والموظف الثاني ما يقدر يلغي طلب أحمد.
4. أكو طلبات جاهزة `DEMO-NEW-1..4` وحالات كمية مختلفة حتى تفحص الفلاتر والتفاصيل. ميّز طلباتك الجديدة بأرقامها ووقتها، لا تعتمد على id ثابت.

## 7. السيارات / ستيكر الزجاج

1. اختار مخزن المركبات التجريبي **9012**. من صفحة الباركود استخدم أول وثاني ستيكر VIN.
2. صوّر السطر النصي تحت HYUNDAI. هذا **OCR نص، مو Code128**. جرّب التكبير والإضاءة والتقاط أفقي وعمودي.
   - المتوقع: رقم 17 خانة، نوع السيارة Elantra 2025/Tucson 2025 من قائمة المتوقع، حفظ مع المستخدم والمخزن والموقع، ونفسه باللوحة/المركبات وبالتطبيق/سجلي.
3. امسح نفس الرقم مرة ثانية.
   - المتوقع: 409 «رقم VIN ممسوح مسبقًا في هذه الجلسة» بدون سجل ثاني.
4. جرّب حرف O أو I أو Q أو طول 16/18 خانة.
   - المتوقع: رفض 400. أرقامنا مصطنعة بصيغة Hyundai ومع خانة تدقيق؛ مو هويات سيارات حقيقية.
5. من التطبيق اطلب تصحيح VIN لرقم جديد صالح غير ممسوح مع سبب. أدمن المنصور يوافق؛ طلب ثاني يرفضه.
   - المتوقع: المقبول يغيّر VIN ويحتفظ بطلب التصحيح، المرفوض ما يغيّره. المحاسب ما عنده صلاحية تصحيح VIN.

## 8. اختبارات سلبية لازم توثّقها

|التجربة|النتيجة المطلوبة|
|---|---|
|GPS `0,0` بعدّ/مسح VIN/إعادة عد/إضافة قطعة|400 ورسالة عربية، بدون حفظ|
|Latitude=91 أو -91، Longitude=181 أو -181، أو موقع ناقص|400 بدون حفظ؛ السماح بخط عرض أو طول صفر وحده إذا الثاني صحيح|
|إذن الموقع مرفوض أو الشبكة انقطعت|رسالة واضحة، لا نجاح وهمي؛ حدث الحالة قبل إعادة الطلب|
|أحمد يرسل مخزن البصرة بعملية المنصور|403 أو 400 حسب نوع الطلب، ما تنحفظ بداتا مخزن آخر|
|مخزن لا يتبع الفرع بطلب إضافة|400 بدون إنشاء طلب|
|محاسب البصرة يشوف/يوافق طلب المنصور|غير مسموح، ماكو تسريب لطلبات خارج النطاق|
|إنشاء موظف/مشرف بنفس رقم هاتف موجود، أو نفس الهاتف بالنوعين|رسالة تكرار، ماكو حساب ثاني|
|عداد معطّل يستخدم token قديم|401|
|كمية سالبة، حقول ناقصة، نص HTML بطلب إضافة|400 أو أخطاء نموذج واضحة، ماكو حفظ|
|CSV/Excel بـ BranchNo. غلط أو WarehouseNo. مو موجود|استيراد مرفوض، رسالة تحدد السطر/الرقم، ما تبدي جلسة جزئية|
|رمز موجود مع مسافات/شرطة|البحث/المسح يطابق الرقم بعد التطبيع، ما يسوي إضافة مكررة|

لا تزوّر GPS على الجهاز الحقيقي حتى تنفذ السالب؛ اختبر هذه الحالات بطلبات API على قاعدة التجربة. خذ accessToken من تسجيل دخول أحمد، ولا تشاركه أو تحفظه بالريبو. استخدم نفس شكل `counts` و`vins/scan` و`recounts/{id}/submit` و`new-part-requests` الموثق بـ `/swagger`.

## 9. إنهاء الجلسة — خلّه آخر خطوة

- نزّل تقرير الفروقات والجلسة وراجع الصفوف الخمسة والقيمة يدوياً. جرّب البحث والصفحات والفلاتر ونطاق الفرع والمخزن.
- المسؤول/السوبر ينهي الجلسة الحية **التجريبية فقط**.
- المتوقع: الحالة «مكتمل»، التقارير والعدّات القديمة تبقى، طلبات الإضافة المفتوحة تنغلق. `/api/v1/sessions/current` يرجع `data:null`، والعد الجديد ومسح VIN يرجعان **409**. إعادة تشغيل الـ seed ما تعيد فتح الجلسة.
- لجولة جديدة أنشئ جلسة بسنة غير مستخدمة من Excel. ورقة `Parts`: `Quantity | Description | Location | Serial | BranchNo.`، وورقة `Vins`: `VIN | WarehouseNo. | VehicleType`. انسخ أرقام **الفرع والمخزن الحقيقية من اللوحة**، مو ids. اختبر الملف الغلط فقط لما ماكو جلسة حية حتى يظهر خطأ الاستيراد بدل «توجد جلسة».
- بعد الاختبار شيل العلم: `set Seed__Demo=` و`set Seed__DemoPassword=`. الداتا تبقى؛ ماكو حذف تلقائي. ماكو تنظيف يلمس بيانات قديمة.

## 10. ورقة تسليم النتيجة

سجّل لكل خطوة: ناجح/فاشل، هاتف ونظام الجهاز، نسخة APK، الرابط، رقم الجلسة والقطعة/الطلب، النتيجة المتوقعة والفعلية، صورة بدون كلمات سر أو token، ووقت مع المنطقة الزمنية. افحص صلاحية الكاميرا وGPS والتكبير وOCR والعمل بعد قطع/رجوع الشبكة على جهاز حقيقي؛ هذي ما تنحسم باختبار HTTP وحده.
